## Things worth remembering

- **The API tokens and MCP server** the owner chose for AI-agent access are not built. They
  need M14 pulled forward, and the MCP server sits on top of that API.
- **A graph is a disclosure surface.** Every node, edge and backlink filters through the one
  permission-checked accessor, per document rather than per subtree. This is mutation-tested.
- **Nothing has been verified in a browser by a human.** Group F browser checks exist for the
  graph; the owner has not looked at it, and only they can sign in to see the real one.

## Task 1 to resume: absolute self-links

`wiki_path` in `crates/gw-store/src/links.rs` treats `https://wiki.ohje.ooguy.com/darm/labor`
as external, so pasting from the address bar records no graph edge. The link works; it is
simply invisible to the graph and to backlinks.

- The value already exists: `GW_PUBLIC_URL=https://wiki.ohje.ooguy.com` is in the deployed
  compose and reaches `gw-web` as `ORIGIN`. **`gw-api` does not receive it.**
- **`gw-store` must not read the environment** — it is a library. The origin arrives through
  an existing seam; see `Store::open` and `crates/gw-api/src/config.rs`.
- **Unset must behave exactly as today.** Never guess from a `Host` header — attacker
  controlled, and the export code documents why.
- Match the **origin**, not the hostname: scheme and port count.
- Do not rewrite stored bodies.
- Needs a mutation in `scripts/mutate.sh` and a compose change passing the variable to
  `gw-api` (edit but do not commit in the Server repo).

## Method that worked, and should continue

- Fresh implementer per task, separate reviewer, fixes looped until clean.
- **Every test watched failing for the right reason** — a compile error is not a failing test.
- **Break something the agent did not choose.** Four vacuous tests were found this way.
- Reviewers were told to attack specific claims, not to "review the diff". Every serious
  finding came from that.
- The ledger `.superpowers/sdd/progress.md` is tracked and is the recovery map.
