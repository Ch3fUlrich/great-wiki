# M7 search — plan (2026-10-08)

Scope: permission-aware full-text search, no assistant, no attachment contents (roadmap,
"M7 is search first"). Decisions: ADR 0003 (FTS5 behind a trait), ADR 0022 (withheld = absent),
ADR 0012 (purge destroys), rule 2 (filter in the retriever, per document, one accessor).

## Design in four lines

1. `documents` gains `body_text` (plain text of the block tree, written wherever `body` is).
   `search_pages` is an FTS5 **external-content** table over `documents(title, body_text)`,
   `tokenize='unicode61 remove_diacritics 2'`, kept current by **triggers** on insert, on
   update of title/body_text, and on delete. Purge is a hard `DELETE FROM documents`, so the
   delete trigger is what makes ADR 0012 hold for the index.
2. The index stores **no path and no state**. A hit is a rowid; path, `deleted_at` and
   permission come from `documents` at query time. So move/rename need no index write, and
   trash/restore is a `deleted_at IS NULL` condition.
3. `SearchIndex` trait (gw-store): `candidates(&self, query, limit) -> Vec<Candidate{doc_id,
   rank, snippet}>`. `Fts5Index` is the implementation. Candidates are **unfiltered by
   design and crate-private to the trait's one caller** (`Store::search_pages_for`), which
   puts every one through `document_for_id` before anything leaves `gw-store`.
4. User text never reaches MATCH raw: tokenise to words, quote each as an FTS5 string
   (`"w"`), prefix-star the last, AND them. No operators, no column filters, no NEAR.

Topics and tasks are small sets already behind permission-checked accessors
(`topics_for`, `board_for`); they are matched in process on those accessors' output (folded
case/diacritics), never from a separate table — there is no fourth path.

## Task 1 — GW-SEARCH-INDEX (files: migration 0016, `search.rs`, writes in
`documents.rs`/`revisions.rs`; tests in `search.rs`)

- `0016_search.sql`: `ALTER TABLE documents ADD COLUMN body_text TEXT`; FTS5 table + 3 triggers.
- `gw_core`: one `body_plain_text(&str) -> String` (JSON block tree → text, via
  `Block::plain_text`) — the single flattener; unparseable body → empty string, never an error.
- Write `body_text` in `create_document` and `append_revision` (same statement as `body`).
- Open-time backfill: rows with `body_text IS NULL` get it computed, then
  `INSERT INTO search_pages(search_pages) VALUES('rebuild')`. Idempotent.
- `trait SearchIndex` + `Fts5Index`; bm25 weights title 10, body 1.
- Tests (red first): finds by title/body; German umlaut folds (`Arzt`↔`Ärzte` stem is not
  promised; `Müller`↔`muller` is); edit changes hits; rename (title) changes hits; move keeps
  hits and returns the new path; trash hides, restore returns; **purge removes the row from
  the FTS table itself** (assert on `search_pages_docsize`/a `MATCH` with trash filter off);
  title outranks body; hostile query strings (`"`, `*`, `NEAR(`, `AND`, `col:x`, empty) return
  without error and without operator semantics; backfill of pre-migration rows.
- Done: `cargo test -p gw-store` green.

## Task 2 — GW-SEARCH-API (disclosure-critical; files: `gw-store/src/search.rs` (accessor
part), `gw-api/src/routes/search.rs`, `routes/mod.rs`; tests `gw-api/tests/search.rs`)

- `Store::search_for(principal, q, limit) -> SearchResults{pages, topics, tasks}`; each hit =
  title, current path, snippet (term marked with `<mark>`… **escaped**: snippet text is
  HTML-escaped by the store before the marks are added, so the web may render it with the one
  allowed sink — see `scripts/check-html-sinks.sh`; if that script forbids it, return
  `[{text, hit}]` segments instead and render without a sink — prefer segments).
- Pages: candidates → `document_for_id(principal, id, Read)` per candidate (baseline hoisted
  via the `_with_baseline` variant) → drop `None`. Over-fetch (limit×5, cap 200) and stop at
  `limit` visible hits. **No count, no total, no "n hidden".** Snippet comes from the
  accessor's own `StoredDocument`, never from the index row.
- Topics: `topics_for`, name match. Tasks: `board_for(principal, None)` + document-anchored
  tasks the board already includes; title match; hit carries task title, status, and the
  path of the page it hangs off (if any).
- `GET /api/search?q=`: empty/blank/over-long q → 200 with empty groups (not 400, not an
  oracle); anonymous allowed (accessor decides). No new permission decision in the handler.
- `scripts/mutate.sh`: `search:` entries — candidate not put through the accessor; accessor
  called as the wrong principal (admin); baseline hoisted from the wrong caller; snippet taken
  from the index instead of the accessor document; trashed filter dropped; topic filter
  bypassed; task filter bypassed; MATCH quoting removed. **All KILLED.**
- Tests: `tests/search.rs` in the `withheld.rs` style — withheld page absent from pages,
  topics and tasks for no-grant and anonymous callers, and the response for a query matching
  *only* a withheld page is byte-identical to a query matching nothing; admin sees it;
  anti-vacuity (a reader does see the open page); result counts equal visible only.
- Done: `cargo test --workspace`, `just mutate search` all killed.

## Task 3 — GW-SEARCH-UI (files: `web/src/routes/suche/+page.{server.ts,svelte}`,
`web/src/lib/search.ts` (+test), header form in `+layout.svelte`)

- Header `<form method="GET" action="/suche" role="search">`, `<input type="search" name="q">`,
  works without JS; `/` focuses it when JS is on.
- `/suche?q=` server load calls `/api/search`; three groups (Seiten, Themen, Aufgaben) with
  headings, empty-state per group, snippet rendered from segments (no `{@html}`), keyboard
  usable (links in a list, visible focus).
- vitest for `search.ts` (segments, grouping, query normalisation); `npm run check` clean.
- `web/scripts/behaviour.mjs`: new group — search finds an open page, never finds a restricted
  one as the guest, form GET works with JS disabled. Screenshot via `web/scripts/shots.mjs`.
- Done: `npm run check`, `npx vitest run`, `just behaviour` group green, screenshot saved.
